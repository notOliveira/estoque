================================================================
ROTEIRO DE FASES — API DE ESTOQUE EM GO + MONGODB
================================================================

OBJETIVO GERAL
--------------
Implementar uma API REST de estoque (CRUD de produtos) em Go +
MongoDB (driver v2), usando net/http da stdlib. Arquitetura em
camadas: domain -> repository -> service -> handler, com config,
db e model de apoio.

O foco deste projeto e APRENDIZADO. Em cada fase, anotar os
conceitos novos (type assertion, bson.M, context, pointer
receiver, sentinel errors, PATCH com ponteiros, etc.).

DECISOES JA TOMADAS
-------------------
- Driver: v2 apenas (remover v1 do go.mod)         [FEITO]
- Update: PUT com todos os campos (tipos diretos,   [MUDOU]
  sem ponteiros). Decidido nesta sessao.
- Interface ProductRepository: definida no pacote repository
  (onde ja esta, simples e funcional)
- ToDomain e metodo nos request DTOs e NAO seta ID nem
  timestamps - o service cuida de ambos.            [NOVO]
- ToResponse e FUNCAO (nao metodo) no pacote model,
  porque Go nao permite metodo em tipo nao-local.
  Aceita-se a assimetria com ToDomain.             [NOVO]
- domain.Product.ID usa bson.ObjectID (driver v2
  consolidou o tipo no pacote bson, sem precisar do
  subpacote /primitive).                            [NOVO]
- Stack: Go 1.22+, MongoDB Community, godotenv, net/http stdlib

CONCEITOS-CHAVE (anotar quando surgirem)
----------------------------------------
1. Type assertion (id.(bson.ObjectID))                [JA USADO]
   No driver v2, ObjectID foi consolidado no proprio
   pacote bson (subpacote /primitive deixou de ser
   necessario). A escolha de caminho e estilistica.
2. Filtros Mongo com bson.M / bson.D                  [JA USADO]
3. context.Context - por que e o primeiro parametro
   de tudo                                            [JA USADO]
4. Pointer receiver (func (r *repo)) vs value receiver
                                                     [JA USADO]
5. Sentinel errors + errors.Is.
6. JSON com ponteiros para PATCH parcial. (Descartado
   nesta sessao - optamos por PUT com campos diretos.)
7. r.PathValue("id") - pattern matching do net/http
   1.22+.
8. Metodo so pode ser definido em tipo declarado no
   mesmo pacote. Para converter domain.Product em
   ProductResponse, o pacote model expõe uma FUNCAO
   ToResponse (nao metodo).                           [JA USADO]
9. Camada model nao deve importar driver (bson/mongo).
   Quem fala de ObjectID e o repository.             [JA USADO]
10. Service e responsavel por setar ID (no Update) e
    timestamps (no Create e Update). Model fica puro.
                                                     [JA USADO]

FASE 6 - Fazer cmd/api/main.go wirar tudo           [PENDENTE]
================================================================

ACOES:
- Carregar config.
- ctx := context.Background().
- client, err := db.Connect(ctx, cfg.MongoURI). Em caso de
  erro, log.Fatal.
- defer func() { _ = client.Disconnect(ctx) }() AQUI (main).
- coll := db.GetCollection(client, cfg.DBName, "products").
- repo := repository.NewMongoProductRepository(coll).
- svc := service.NewProductService(repo).
- h := handler.NewProductHandler(svc).
- mux := http.NewServeMux().
- mux.HandleFunc("POST /products", h.Create).
- mux.HandleFunc("GET /products", h.List).
- mux.HandleFunc("GET /products/{id}", h.Get).
- mux.HandleFunc("PUT /products/{id}", h.Update).
- mux.HandleFunc("DELETE /products/{id}", h.Delete).
- log.Printf("server on :%d", cfg.Port).
- http.ListenAndServe(":"+strconv.Itoa(cfg.Port), mux).

CONCEITO: Dependency injection manual - cada camada recebe a
anterior por construtor, sem framework.
