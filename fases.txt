ROTEIRO DE FASES — API DE ESTOQUE EM GO + MONGODB
================================================================

OBJETIVO GERAL
--------------
Implementar uma API REST de estoque (CRUD de produtos) em Go +
MongoDB (driver v2), usando net/http da stdlib. Arquitetura em
camadas: domain -> repository -> service -> handler, com config,
db e model de apoio.

O foco deste projeto e APRENDIZADO. Em cada fase, anotar os
conceitos novos (type assertion, bson.M, context, pointer
receiver, sentinel errors, PATCH com ponteiros, etc.).

DECISOES JA TOMADAS
-------------------
- Driver: v2 apenas (remover v1 do go.mod)         [FEITO]
- Update: PATCH parcial com *string / *int / *float64
- Interface ProductRepository: definida no pacote repository
  (onde ja esta, simples e funcional)
- Stack: Go 1.22+, MongoDB Community, godotenv, net/http stdlib

CONCEITOS-CHAVE QUE VAO APARECER (anotar quando surgirem)
----------------------------------------------------------
1. Type assertion (id.(primitive.ObjectID)) - o que e any e
   como "tipar" de volta.                              [JA USADO]
2. Filtros Mongo com bson.M / bson.D - maps vs ordered
   docs.                                              [JA USADO]
3. context.Context - por que e o primeiro parametro de
   tudo.                                              [JA USADO]
4. Pointer receiver (func (r *repo)) vs value receiver.
5. Sentinel errors + errors.Is.
6. JSON com ponteiros para PATCH parcial.             [JA USADO]
7. r.PathValue("id") - pattern matching do net/http 1.22+.

FASE 2A - Consertar BUGS de compilacao             [URGENTE]
================================================================

Esses dois arquivos NAO COMPILAM. Sao os primeiros a olhar
amanha:

BUG 1 - domain/product.go
  O struct Product usa `primitive.ObjectID`, mas o import de
  `primitive` foi removido junto com o driver v1. So sobra o
  import "time". Resultado: erro de compilacao.

  Como corrigir:
  - Decidir de onde vem primitive.ObjectID no driver v2.
    No v2, o caminho certo e
    "go.mongodb.org/mongo-driver/v2/bson/primitive".
  - Adicionar esse import.

BUG 2 - internal/repository/product.go
  Linhas 43 e 57 usam `primitive.ObjectID` e
  `primitive.ObjectIDFromHex`, mas o arquivo so importa
  "bson" e "mongo" do v2 (sem "/primitive"). Erro de
  compilacao.

  Como corrigir:
  - Adicionar o import
    "go.mongodb.org/mongo-driver/v2/bson/primitive".

CONCEITO: Imports explicitos em Go. Diferente de outras
linguagens, nao existe "import implicito" - se voce usa um
simbolo, precisa importar o pacote dele. Caso contrario,
compilador reclama.

FASE 6 - Fazer cmd/api/main.go wirar tudo           [PENDENTE]
================================================================

ACOES:
- Carregar config.
- ctx := context.Background().
- client, err := db.Connect(ctx, cfg.MongoURI). Em caso de
  erro, log.Fatal.
- defer func() { _ = client.Disconnect(ctx) }() AQUI (main).
- coll := db.GetCollection(client, cfg.DBName, "products").
- repo := repository.NewMongoProductRepository(coll).
- svc := service.NewProductService(repo).
- h := handler.NewProductHandler(svc).
- mux := http.NewServeMux().
- mux.HandleFunc("POST /products", h.Create).
- mux.HandleFunc("GET /products", h.List).
- mux.HandleFunc("GET /products/{id}", h.Get).
- mux.HandleFunc("PUT /products/{id}", h.Update).
- mux.HandleFunc("DELETE /products/{id}", h.Delete).
- log.Printf("server on :%d", cfg.Port).
- http.ListenAndServe(":"+strconv.Itoa(cfg.Port), mux).

CONCEITO: Dependency injection manual - cada camada recebe a
anterior por construtor, sem framework.
